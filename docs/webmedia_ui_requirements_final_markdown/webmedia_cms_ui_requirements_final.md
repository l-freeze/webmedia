# WEBメディア CMS UI設計要件書 最終版

## 1. 目的

このCMSは、1人〜2人程度で運用するWEBメディア向けの管理画面である。記事の作成、編集、公開、非公開、公開予約、更新履歴管理、バージョン管理、固定ページ管理、メディア管理、問い合わせ管理、サイト設定を、シンプルかつ迷わず行えることを目的とする。

大規模な多人数CMSではなく、1人運営を主軸にした軽量で実務的なCMSとする。

## 2. 基本方針

### 優先すること

- 見やすい
- 分かりやすい
- 操作に迷わない
- 長時間作業しても疲れにくい
- 記事編集に集中できる
- 公開事故を防げる
- 過去の状態へ戻せる
- 1人運営でも安全に管理できる

### 優先しないこと

- 過剰な装飾
- 派手なアニメーション
- 複雑な承認ワークフロー
- 大人数向けの高度な権限管理
- 最初からの高度な分析機能

## 3. デザイン方針

- 管理画面らしい落ち着いたUIにする
- 白または淡いグレーを基調にする
- 文字色は濃いグレーを基本にする
- 主要操作は青系などの落ち着いたアクセントカラーにする
- 危険操作は赤系で明確にする
- 成功状態は緑系、警告状態は黄系で表現する
- 情報の階層、ボタン、フォーム、ステータス表示を明確にする
- 一覧画面は実務上の視認性を重視する

## 4. 対象デバイス

- 主対象はPC
- タブレットでも最低限操作できること
- スマホでは簡易管理ができ、表示が崩れないこと
- 長文記事編集はPC利用を前提としてよい

## 6. 必須画面

## 6.1 ログイン画面

### 目的

管理者がCMSへ安全にログインできること。

### 必須要素

- メールアドレス入力
- パスワード入力
- ログインボタン
- パスワード再設定導線
- ログインエラー表示

### デザイン要件

- 中央寄せのシンプルなログインカード
- 入力項目とボタンが分かりやすい
- エラー時に原因が把握しやすい

## 6.2 ダッシュボード

### 目的

ログイン直後に、サイト運営状況と次に行う作業を把握できること。

### 必須要素

- 公開中記事数
- 下書き数
- 公開予約数
- 非公開記事数
- 最近更新した記事
- 最近作成した記事
- 最近の問い合わせ
- クイックアクション

### クイックアクション

- 新規記事作成
- 記事一覧へ
- 下書き一覧へ
- 公開予約一覧へ
- 問い合わせ一覧へ
- メディア管理へ

## 6.3 記事一覧画面

### 目的

記事の検索、絞り込み、状態確認、編集、複製、削除を行えること。

### 表示項目

- タイトル
- ステータス
  - 下書き
  - 公開中
  - 公開予約
  - 非公開
  - ゴミ箱
- カテゴリ
- タグ
- 作成日
- 更新日
- 公開日時
- 予約公開日時
- 最終更新者
- 操作
  - 編集
  - プレビュー
  - 複製
  - ゴミ箱へ移動

### 機能

- キーワード検索
- ステータス絞り込み
- カテゴリ絞り込み
- タグ絞り込み
- 並び替え
- 一括操作
- ページネーション

### デザイン要件

- テーブル形式を基本とする
- ステータスは色付きラベルで識別しやすくする
- 公開予約中の記事が一覧上で明確に分かること

## 6.4 記事編集画面

### 目的

記事の作成、編集、下書き保存、公開、非公開、公開予約、SEO設定、OGP設定、履歴確認を1画面内で行えること。

### 必須入力要素

- タイトル
- スラッグ
- 本文エディタ
- アイキャッチ画像
- カテゴリ
- タグ
- 抜粋または説明文
- 公開ステータス
- 公開日時
- 予約公開日時
- SEOタイトル
- meta description
- canonical URL
- noindex設定
- OGPタイトル
- OGP説明文
- OGP画像

### 本文エディタ機能

- 見出し
- 段落
- 太字
- リンク
- 箇条書き
- 番号付きリスト
- 引用
- 画像挿入
- 表
- 埋め込み
- プレビュー
- Markdownまたはリッチテキスト対応

### 必須操作

- 下書き保存
- 公開
- 非公開にする
- 公開予約
- 予約解除
- プレビュー
- 更新履歴を開く
- バージョン一覧を開く
- ゴミ箱へ移動

### デザイン要件

- 本文エリアを広く取る
- 主要操作は右カラムまたは固定フッターにまとめる
- 公開状態、予約状態、保存状態が常に分かること
- 公開、非公開、削除、復元には確認ダイアログを出す
- SEO設定とOGP設定は折りたたみ可能でもよい

## 6.5 公開予約UI

### 目的

記事を指定日時に自動公開できるようにする。

### 必須要素

- 公開日選択
- 公開時刻選択
- タイムゾーン表示
- 現在の公開状態表示
- 公開予約確定ボタン
- 予約解除ボタン
- 予約中ステータス表示

### 表示すべき情報

- 現在時刻
- 設定済み予約日時
- 公開予定までの状態
- 予約が解除された場合の状態

## 6.6 記事プレビュー画面

### 目的

公開前に、実際のフロント表示に近い状態で記事を確認できること。

### 必須要素

- PC表示プレビュー
- スマホ表示プレビュー
- 下書き内容の反映
- 記事編集画面へ戻る導線
- 現在のステータス表示

## 6.7 更新履歴 / バージョン管理画面

### 目的

過去の編集履歴を確認し、必要に応じて差分確認や復元を行えること。

### 表示項目

- バージョン番号
- 現在版表示
- 保存日時
- 更新者
- 更新内容のメモ
- ステータス変更履歴
- 差分確認ボタン
- 復元ボタン

### 機能

- バージョン一覧表示
- 2バージョン比較
- 差分表示
- 過去バージョンへの復元
- 誰がいつ何をしたかの確認
- 復元前の確認ダイアログ

### 差分表示

- 追加された内容
- 削除された内容
- 変更された内容
- タイトル、本文、SEO情報、公開設定の差分

## 6.8 固定ページ管理画面

### 目的

記事とは別に、運営上必要な固定ページを管理できること。

### 対象ページ例

- 運営者情報
- プライバシーポリシー
- 問い合わせ
- 利用規約
- 免責事項
- 広告掲載について

### 固定ページ一覧の必須項目

- ページタイトル
- スラッグ
- ステータス
  - 下書き
  - 公開中
  - 非公開
- 作成日
- 更新日
- 最終更新者
- 操作
  - 編集
  - プレビュー
  - 複製
  - ゴミ箱へ移動

### 固定ページ編集の必須要素

- ページタイトル
- スラッグ
- 本文エディタ
- 公開ステータス
- SEOタイトル
- meta description
- canonical URL
- noindex設定
- OGPタイトル
- OGP説明文
- OGP画像
- プレビュー
- 保存
- 公開
- 非公開
- 更新履歴
- バージョン管理

### デザイン要件

- 記事編集画面と操作体系を揃える
- カテゴリやタグは原則不要
- SEO設定は記事と同等に行えること
- 固定ページも履歴・復元できること

## 6.9 カテゴリ管理画面

### 目的

記事分類の大枠となるカテゴリを管理できること。

### 必須要素

- カテゴリ一覧
- 新規作成
- 編集
- 削除
- スラッグ設定
- 表示順
- 親カテゴリ設定
- 使用記事数
- SEOタイトル
- SEO説明文
- OGP画像

## 6.10 タグ管理画面

### 目的

記事に付与する補助分類としてタグを管理できること。

### 必須要素

- タグ一覧
- 新規作成
- 編集
- 削除
- スラッグ設定
- 使用記事数
- SEOタイトル
- SEO説明文

## 6.11 メディア管理画面

### 目的

記事や固定ページで使う画像・ファイルを管理できること。

### 必須要素

- 画像アップロード
- 画像一覧
- サムネイル表示
- ファイル名
- ファイル形式
- ファイルサイズ
- アップロード日
- altテキスト
- キャプション

- グリッド表示 / リスト表示切替

### 目的

### 必須要素

- 問い合わせ一覧
- 名前
- メールアドレス
- 件名
- 内容
- 受信日時
- ステータス
  - 未対応
  - 対応中
  - 対応済み
- 詳細表示
- 管理用メモ
- ステータス変更

## 6.13 サイト設定画面

### 目的

サイト全体に関わる基本情報や外部連携情報を管理できること。

### 必須要素

- サイト名
- サイト説明
- ロゴ
- ファビコン
- デフォルトOGP画像
- フッター情報
- SNSリンク
- Google Analytics ID
- Google Tag Manager ID
- Search Console確認タグ
- AdSenseタグ
- 問い合わせ通知先メールアドレス

## 6.14 ゴミ箱画面

### 目的

削除済みの記事や固定ページを確認し、復元または完全削除できること。

### 必須要素

- 削除済み記事一覧
- 削除済み固定ページ一覧
- 削除日時
- 削除者
- 復元
- 完全削除

### デザイン要件

- 削除済みであることが明確に分かること
- 完全削除は確認ダイアログを必須にする
- 復元後の状態が分かること

## 7. 状態設計

各画面で以下の状態を考慮すること。

- 通常状態
- 読み込み中
- 保存中
- 保存成功
- 保存失敗
- データなし
- 検索結果なし
- バリデーションエラー
- 権限不足
- 削除確認
- 復元確認
- 公開確認
- 非公開確認
- 公開予約確認
- 予約解除確認

## 8. 操作性要件

- 主要ボタンは常に分かりやすく配置する
- 危険操作には確認ダイアログを出す
- 下書き保存、保存中、保存完了の状態を表示する
- 公開予約中であることを明確に表示する
- 更新履歴とバージョン復元へすぐ遷移できること
- 記事編集画面と固定ページ編集画面の操作体系を揃える
- 一覧画面では検索、絞り込み、並び替えを使いやすくする

## 10. デザイン出力時の要望

- ワイヤーフレームではなく、実際に使えそうなUIデザインにすること
- 過剰に装飾しないこと
- 実務画面としての使いやすさを優先すること
- 画面ごとの整合性を保つこと
- CMS全体で同じデザインルールを使うこと
- PC版とスマホ版の両方を作ること
- 記事編集、公開予約、更新履歴、バージョン管理、固定ページ管理は特に明確に表現すること
