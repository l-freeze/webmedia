    - route-level permission は `Application/Auth/AuthorizeRoute` UseCase と `RequireCmsPermissionMiddleware` で扱う。
    - resource-level permission は `Domain/Policy/ArticlePolicy` が `CmsActor` と `Article` を見て判定し、`ArticleCreatePermission` / `ArticleUpdatePermission` / `ArticlePublishPermission` / `ArticleDeletePermission` / `ArticleRestorePermission` を発行する。
    - `Article/Save`、`Article/Delete`、`Article/Restore` は Application Query port を持たず、C 側の読み込みと保存を `Domain/Repository/IArticleRepository` に寄せた。
    - Article Entity の作成 / 更新 / 削除 / 復元は許可済み操作 value を受け取る形にした。
    - `Application/Auth/Policy` と `PdoArticlePolicyQuery` を削除し、Application `<Feature>/<Action>` ルールの例外をなくした。
    - PHPUnit、PHPStan、HTTP 経由のログイン、記事作成、記事更新、記事削除、記事復元を確認済み。検証用記事と版履歴は削除済み。
  - `CmsGuard::currentUser()` を認証済み領域用の non-null API にし、nullable なユーザー解決は Guard 内部へ閉じた。未ログイン redirect は `RequireCmsSessionMiddleware` に集約し、Controller 側の重複 redirect 分岐は削除した。
  - ログイン後にダッシュボード、記事、固定ページ、カテゴリ、タグ、メディア、問い合わせ、設定、ゴミ箱を HTTP 確認。
  - 管理ログインの試行回数制限を追加した。
    - `cms_login_attempts` に success / failure / blocked を記録する。
    - 10分間で email + IP の failure が5回、または IP 全体の failure が20回に達した場合、password verify 前に blocked とする。
    - 通常失敗と blocked の画面文言は同じ `ログインに失敗しました。時間をおいて再度お試しください。` にした。
    - HTTP 経由で CSRF 付き POST を6回実行し、failure 5件、blocked 1件、SecurityLog `cms.login blocked` を確認済み。検証用 login attempt 行は削除済み。
    - Application / Presentation の呼び出し規約は、複数引数を named arguments 優先、単一引数かつ意味が明白な呼び出しは positional arguments 可とし、既存コードも合わせた。抽象的な public API は単一引数でも named arguments を優先し、private method の単一引数呼び出しは named arguments 不要とした。
    - 失敗ログイン試行の上限判定は `hasTooManyFailedLoginAttempts()` に閉じ、`execute()` から中間の集計値を外へ出さない形にした。
    - 認証情報で有効なユーザーを取得する処理は `findUserByValidCredentials()` に閉じ、`execute()` の失敗分岐を `User|null` の判定に寄せた。
    - ログイン試行回数の集計開始時刻は小さすぎる private method にせず、`hasTooManyFailedLoginAttempts()` 内の local 変数にした。
    - `/admin/security/login-attempts` を追加し、`security.manage` を持つ管理者が CMS ログイン制限を解除できるようにした。
    - 解除は履歴削除ではなく `cms_login_attempt_resets` への append-only event として保存し、集計時に最新解除時刻以降の failure だけを数える。
  - 記事作成、編集、プレビュー、履歴、版プレビュー、復元、削除を HTTP 経由で確認。
  - カテゴリ / タグの作成、更新、削除を HTTP 経由で確認。
  - 検証用データは削除済み。
  - メディア削除フォームの inline `onsubmit` をやめ、既存の `data-confirm` 共通処理へ寄せた。
- CMS 記事編集画面で `sr-only` radio input に共通 `w-full` が当たり横スクロールが出ていたため、CMS layout の Presentation 側で修正。
- BusinessAudit という別ログ種別は作らず、既存の `AuditEvent` に業務イベントを集約する方針にした。

- CMS 状態変更 Audit は `AuditMiddleware` が最終出力する形に集約した。Controller / UseCase から `AuditEvent` は直接 dispatch しない。
- 記事/固定ページ/分類/問い合わせ/管理者/設定/メディア削除は、成功時だけ Controller から `AuditReporter` へ業務要約を注入し、middleware が HTTP envelope と合わせて 1 件の AuditEvent として記録するようにした。
- 監査対象の状態変更成功時は `AuditReporter` の業務要約を必須にし、状態変更なしの validation failure などは Audit success として記録しない方針へ整理した。メディアアップロードにも `media.uploaded` 要約を追加し、状態変更 route の Controller が `AuditReporter` を注入・呼び出すことをテストで検査するようにした。
- Pub/Sub 方式の将来方針に、同期 EventBus では outbox を導入せず、非同期化・retry 保証・外部配信などが必要になった時点で再検討する条件を追記した。
- PHP 8.5 の URI extension を使い、production code の `parse_url()` を全て置き換えた。malformed `REQUEST_URI` は Framework HTTP の `MalformedRequestException` として扱い、Kernel entrypoint で bad request `Response` に変換する。`handleGlobals()` は最終 `Response` の送信に寄せ、canonical URL は不正な base/path では出力しない。
- `article.created` / `article.trashed` は HTTP 経由で記録と表示を確認済み。検証用記事は削除済み。
